# Evaluations

Every claim in the project README is backed by one of these. Each suite is
self-contained: it builds its harnesses from the CLI, runs live, scores every
arm with the **same** deterministic checks, and commits its `RESULTS.md`.

| Suite | Question | Scale | Verdict |
|---|---|---|---|
| [article-extractor](article-extractor/README.md) | Does a harness rescue a model that cannot hold the contract? | 32 URLs × 3 epochs × 9 arms | Haiku 3% → 65%, 12× cheaper per success; no significant gain on any other model |
| [article-digest](article-digest/README.md) | Does it still earn its place on frontier models? | 10 URLs × 2 epochs × 4 arms | Opus 5 / Sonnet 5: 80% → 100% success, cost per success flat |
| [page-audit](page-audit/README.md) | What do frontier models still get wrong, and is it visible? | 6 URLs × 1 epoch × 4 arms | Silently-wrong runs 5/6 and 3/6 raw → 0/6 harnessed |

Read them in that order: they were built in that order, and each one exists
because the previous one left a question open.

## The shared method

- **One prompt, one tool, one loop policy.** In article-digest and page-audit
  the raw arms run through hiveloom too, with only the validators and
  `loop.require_verification` removed. The measured delta is therefore
  verification and retry-with-feedback, not incidental prompt differences.
- **One scorer for every arm**, applied against a live re-fetch rather than
  the model's own tool output, so a truncated or stale fetch cannot score as
  correct.
- **Cost from hiveloom's own accounting**, prompt caching included, so cost
  per success is comparable across arms.
- **Results are committed.** `RESULTS.md` is generated by `scripts/score.py`
  and checked in; the raw per-run JSONL under `results/` is not.

The README charts are drawn from `article-extractor/RESULTS.md` by
[`docs/assets/make_plots.py`](../docs/assets/make_plots.py). Their numbers are
transcribed, so re-running a sweep means updating both files.

## Caveats that apply to all of them

- These are smoke-to-probe scale (96, 80, and 24 runs). Treat single-digit
  deltas as noise; the *shape* of a failure is the finding, not its rate.
- The datasets are live URLs, which drift. Scorers tolerate a bounded number
  of misses for that reason, and `page-audit/scripts/preflight.py` recomputes
  its truncation ground truth before a run.
- Prices are list price at run time. Sonnet 5's introductory rate expires
  2026-08-31, after which the cost columns of the frontier suites move.
- Running the frontier suites needs API access to Opus 5 and Sonnet 5, plus
  entries for them in `~/.hiveloom/models.yaml` — the builtin `claude` catalog
  is fixed and predates those ids. See each suite's README.

## Running one

```bash
cd evals/<suite>
export ANTHROPIC_API_KEY=sk-...
./scripts/setup_harnesses.sh    # builds harnesses/ from the hiveloom CLI
python3 scripts/run_eval.py     # live, resumable
python3 scripts/score.py        # rewrites RESULTS.md
```

`article-extractor` is the exception: it is an [Inspect](https://inspect.aisi.org.uk/)
task with its own `pyproject.toml`, driven by `scripts/run_all_arms.sh`.
